# Pure-PL V1 baseline: 10-run VCK5000 performance report

## 1. Measurement status

This report records a fresh board campaign performed on 2026-08-30.  Both
configurations completed all warmup and measured launches on the same VCK5000
and passed their functional gates.  The requested campaign contains 10
measured launches, not 100.  Results from the older 25-run campaign are not
substituted for the new raw samples.

| Item | Pure-PL V1 baseline | V19 proposed peer |
|---|---|---|
| Implementation | BF16 attention entirely in PL | PL transport/quantization plus 64 AIE tiles |
| XCLBIN SHA-256 | `15b01daedc8d6ba497eaeb2644b299d9bc46c6069d06580db8025fe01cce9b2c` | `1022984139d8e79aa99a5c4ebafd3d0d5eeae4e341d89552b3f1b2adcf1b522f` |
| Workload | B=8, S=32, Hq/Hkv=32/8, D=128 | Same |
| I/O precision | BF16/BF16 | BF16/BF16 |
| Main arithmetic | BF16 QK, FP32 softmax/PV | INT8 QK, FP32 softmax/PV |
| Warmup / measured / seed | 5 / 10 / 7 | 5 / 10 / 7 |
| Timing scope | H2D + kernel + D2H | Same |
| Device / XRT | VCK5000 `0000:af:00.1` / 2.15.225 | Same |
| PL clock | 300 MHz | 300 MHz |

The comparison is workload- and timing-scope-matched, but not an
arithmetic-precision-identical comparison.  Performance and numerical error
must therefore be reported together.

## 3. Numerical accuracy

Both implementations pass the Host's functional threshold.  The pure-PL
baseline is more accurate under the retained FP32 CPU oracle and also passes
the internal 0.003 maximum-error target; V19 does not pass that stricter
internal target.

| Metric | Pure-PL V1 | V19 proposed |
|---|---:|---:|
| Mean absolute error | 0.000192967 | 0.000311509 |
| P99 absolute error | 0.001064956 | 0.001426667 |
| P99.9 absolute error | 0.001861870 | 0.002088130 |
| Maximum absolute error | 0.001953006 | 0.003970712 |
| Functional check | PASS | PASS |
| Internal 0.003 target | PASS | FAIL |

The correct paper statement is therefore that V19 trades some numerical
accuracy for a two-order-of-magnitude E2E throughput improvement while
remaining within the declared functional bound.  It is not valid to claim
bitwise or precision-equivalent acceleration.

## 4. Routed resources and timing

| Metric | Pure-PL V1 | V19 proposed |
|---|---:|---:|
| AIE compute tiles | 0 | 64 |
| Full-design registers | 43,710 | 131,927 |
| Full-design CLB LUT | 34,815 | 78,130 |
| Full-design LUT as memory | 4,411 | 16,199 |
| Full-design BRAM tiles | 45 | 216 |
| Full-design URAM | 131 | 0 |
| Full-design DSP | 19 | 24 |
| Routed WNS / TNS at 300 MHz | 0.000 / 0.000 ns | +0.006 / 0.000 ns |

The pure-PL baseline is not compute-resource-saturated: it uses only 19 DSPs
and stores substantial state in 131 URAMs.  Its kernel occupies 99.78379% of
E2E p50, while V19 kernel execution occupies 78.00623%.  Hence V1 is
compute/dataflow-bound inside the kernel, not PCIe-transfer-bound.  V19 moves
the dominant matrix work into all 64 AIE tiles and changes the remaining E2E
bottleneck composition; H2D/D2H overhead becomes visible only after the
kernel is reduced to about 4 ms.

## 5. Paper-use conclusions and limits

1. The fresh same-day result supports a 128.29x kernel-p50 speedup and a
   100.29x E2E-p50 speedup over the true 0-AIE pure-PL V1 baseline for the
   fixed B=8/S=32 workload.
2. The result is stable over 10 runs: V1 kernel min/max are
   509.884662/509.954568 ms and E2E min/max are
   510.995331/511.057203 ms.
3. The primary acceleration is architectural compute/dataflow relocation, not
   host transfer optimization: V1 H2D+D2H p50 is about 1.10 ms, while its
   kernel alone is about 510 ms.
4. Do not describe the result as a full Llama-3 model speedup.  It measures one
   dense causal-GQA attention workload and excludes QKV projections, MLP,
   layer normalization, KV-cache management and token sampling.
5. Do not describe the comparison as equal precision.  The baseline uses BF16
   QK while V19 uses INT8 QK, and the measured error table must accompany the
   speedup table.
6. Ten samples satisfy this requested campaign, but a larger campaign is still
   preferable for tail-latency claims.  In particular, p95 with N=10 is the
   maximum sample under nearest-rank statistics and should not be overread.
